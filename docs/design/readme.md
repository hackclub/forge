# How to write a good README

*inspired from fallout.hackclub.com*

Hmm, so you have made your project and now are writing the README. See, you have overcome the difficult part of a project, but writing a README is one of the important things before submitting your design for review.

Your README is the first impression of the people that see your project. Make it awesome\!\! Someone reading your README should understand that:

* What your project is  
* What it does / What is the purpose of it  
* Why it exists

If they have to open even a single file, then your README isn't doing a good job.

To start writing your README, you can start with an overview of your project that can tell the user about your project in 3-4 lines. After that you can have these sections in your README:

* A couple sentences on why you made the project  
* PICTURES OF YOUR PROJECT (a picture is worth more than thousand words)  
  * A screenshot of a full 3D model with your project  
  * A screenshot of your PCB, if you have one  
  * A screenshot of your schematic, if you have one  
* A wiring diagram, if you're doing any wiring that isn't on a PCB  
* How to assemble: step-by-step guide  
* How to flash (if using MCU)  
* A BOM in table format at the end of the README  
* Known Issues (if any)  
* Credits (Don’t forget this, if you used any open-source firmware or others' work)

You can ignore things that aren't applicable to your project

For learning more about Markdown, I'd recommend [this guide](https://gist.github.com/cuonggt/9b7d08a597b167299f0d).
